# AI 眼镜现场检查成本估算

> 评估日期：2026-07-16。价格来源：[阿里云百炼模型价格](https://help.aliyun.com/zh/model-studio/model-pricing) 与 [Qwen-Omni 实时模型计费说明](https://www.alibabacloud.com/help/zh/model-studio/realtime)。本文统一按**中国内地（北京）按量后付费标价**测算；不计免费额度、限时优惠、网络、存储、设备和人工复核成本。

## 1. 三种主识别方案

| 方案 | 主识别模型与输入 | 单次识别成本 | 5 分钟常规检查（80 次识别） | 适用性 |
| :--- | :--- | ---: | ---: | :--- |
| **方案 A：实时全模态** | `qwen3-omni-flash-realtime`，图片帧 + 持续音频流 | **约 ¥0.0060**（明确假设见第 3 节） | **约 ¥0.478 起** | 可实时听、看、对话；成本最高，且单连接最多 8 轮。 |
| **方案 B：VL 主识别** | `qwen3-vl-plus`，每次将 Base64 图片和提示词发送给模型 | **¥0.001891–¥0.002730**（真实日志样本） | **¥0.151–¥0.218** | 成本最低，适合默认的图片隐患识别。 |
| **方案 C：3.7 主识别** | `qwen3.7-plus`，每次将 Base64 图片和提示词发送给模型 | **¥0.003590–¥0.004368**（同 Token 口径） | **¥0.287–¥0.349** | 识别与复杂判断由一个模型完成，成本约为 VL 的 1.6–1.9 倍。 |

**推荐：** 常规巡检优先方案 B；确需更强的单模型判断/法规解释时使用方案 C；只有需要连续音频输入、实时互动时使用方案 A。

| `qwen3.7-plus` | ≤256K：¥2；256K–1M：¥6 | ≤256K：¥8；256K–1M：¥24 | 方案 C。预算采用标价，不采用页面显示的限时 8 折。 |

`qwen3-omni-flash-realtime` 的音频 Token 换算为：**音频秒数 × 12.5**；图片按 32 × 32 像素计算 Token，单图最少 4、最多 1,280 Token。实时多轮会话会重复计入上下文内的历史图片、音频和文本，因此实际账单可能高于本表的单轮基准。

## 3. 单次识别成本

### 3.1 方案 A：`qwen3-omni-flash-realtime`

实时方案没有天然的“单张图片请求”边界。为与方案 B、C 可比，以下将一次识别定义为：**1 张约 1,000 Token 的图片 + 200 Token 提示词 + 4 秒音频 + 90 Token 纯文本结果**。

| 成本项 | 用量与单价 | 成本 |
| :--- | :--- | ---: |
| 文本输入 | 200 × ¥2.2 / 百万 | ¥0.000440 |
| 图片输入 | 1,000 × ¥3.9 / 百万 | ¥0.003900 |
| 音频输入 | 4 秒 × 12.5 = 50 Token；50 × ¥18.9 / 百万 | ¥0.000945 |
| 仅文本输出 | 90 × ¥8.3 / 百万 | ¥0.000747 |
| **单次合计** | 仅文本输出 | **¥0.006032** |

若模型改为语音回复，输出应按“文本 + 音频”或“仅音频”单价计算，成本会提高；现场检查应设置为 `modalities=["text"]`。

### 3.2 方案 B、C：图片 Base64 主识别

客户端 `DashScopeVlService` 的 `[BILLING_EVAL]` 有两组 `qwen3-vl-plus` 真实用量。将同一组输入/输出 Token 代入 `qwen3.7-plus` 价格，得到主识别的横向预算：

| 场景 | 输入 / 输出 Token | `qwen3-vl-plus` | `qwen3.7-plus` |
| :--- | :--- | ---: | ---: |
| 静默巡检、无隐患 | 1,731 / 16 | ¥0.001891 | ¥0.003590 |
| 语音触发、有隐患 | 1,820 / 91 | ¥0.002730 | ¥0.004368 |

计算公式：`成本 = 输入 Token × 输入单价 / 1,000,000 + 输出 Token × 输出单价 / 1,000,000`。方案 C 的实际输出若包含思考 Token 或长整改文本，应按真实 `completion_tokens` 重新结算。

## 4. 5 分钟完整检查成本

### 4.1 识别次数假设

按现有抓拍策略外推：有隐患约 5 秒一次（60 次/5 分钟）、常规混合约 3.75 秒一次（80 次/5 分钟）、无隐患高频约 2.5 秒一次（120 次/5 分钟）。

| 5 分钟场景 | 识别次数 | 方案 A：Omni 实时全模态* | 方案 B：VL 主识别 | 方案 C：3.7 主识别 |
| :--- | ---: | ---: | ---: | ---: |
| 多隐患／低频 | 60 | ¥0.376 起 | ¥0.113–¥0.164 | ¥0.215–¥0.262 |
| 常规混合 | 80 | **¥0.478 起** | **¥0.151–¥0.218** | **¥0.287–¥0.349** |
| 无隐患／高频 | 120 | ¥0.681 起 | ¥0.227–¥0.328 | ¥0.431–¥0.524 |

\* 方案 A 按每帧 1,000 图片 Token、每次 200 文本输入 Token、每 5 分钟连续 300 秒音频（3,750 Token）、每次 90 文本输出 Token计算；不包含多轮上下文重复输入。因此“起”表示保守的单轮下限，而非账单上限。

方案 A 的 80 次识别超过 `qwen3-omni-flash-realtime` 单连接最多 8 轮的限制。若每次识别都触发模型响应，5 分钟内至少要切分为 10 个会话；重复发送系统提示词、重建上下文会进一步增加实际成本。这也是它不适合作为高频定时抓拍主识别方案的原因。

## 5. 落地建议与计费校准

1. **方案 B：** 将 `qwen3-vl-plus` 固定为高频帧的主识别模型，保持短 JSON 输出与单次输入低于 32K Token。
2. **方案 C：** 可以独立作为主识别方案，但应记录其真实输出 Token；如结果中包含长推理或整改文本，不能沿用本表的短输出成本。
3. **方案 A：** 只在“边说边看”的交互模式启用；使用纯文本输出、VAD 和相似帧过滤，并在每次 `response.done` 记录 `input_tokens_details` 与输出 usage。
4. **月度校准：** 将模型、检查时长、图片数、音频秒数、`prompt_tokens`、`completion_tokens`、实时分模态 usage 进入成本日志；每月以百炼账单更新本表的图片 Token 与输出 Token 假设。

## 6. 算粒保底提示

若 1 粒 = ¥0.1、按 3 倍成本加成，方案 B 的短图片识别仍低于 1 粒保底价。方案 A 和方案 C 的完整 5 分钟检查成本显著更高，应按检查场次、时长或实际 Token 分档扣减，不宜直接套用“单次图片识别 1 粒”的结论。
