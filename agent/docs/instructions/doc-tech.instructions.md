# 技术文档编写规范

- 面向初学者讲解，表达简洁；首次出现的关键概念要解释清楚。
- 优先使用有序列表、无序列表和表格组织内容；流程或关系较复杂时，再使用流程图辅助理解。
- 正文以概念和原理为主，不绑定到某个实际 Demo 的文件路径或具体实现；有助于理解的示例可按需加入，并与相关 Demo 保持一致。
- 提供代码示例时，在关键学习点添加简短中文注释；注释说明学习要点，不逐行复述显而易见的代码。
- 涉及 API、版本、兼容性或安全等易变化内容时，优先查阅官方资料，并注明来源和适用版本；无法核实的内容应标为待确认，不凭记忆断言。
- 保证内容完整闭环、前后术语一致；合并重复说明，避免同一知识点在多处反复解释。
- 完成前检查示例与说明是否一致、代码注释是否清楚，以及是否存在遗漏或重复。

## 学习小结

- 不使用固定章节模板或标题白名单。
- 根据主题、可用资料和用户目标拟定章节提纲，先交由用户确认或调整；确认后再撰写正文。
- 用户已给出章节提纲时，直接沿用，不重复要求确认。
- 章节按主题需要组织，可涵盖概念、原理、使用场景、API、示例、边界或排查等；不为填满清单而强行添加章节。
- 从技术文档视角解释职责、流程、输入输出和约束，不逐行翻译现有 Demo 代码，也不依据文件数量或目录结构扩展章节。
- 上下文不足时，不虚构实现细节；无依据的内容省略或明确标为待确认。
